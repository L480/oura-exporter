# oura-exporter

[![CI](https://github.com/L480/oura-exporter/actions/workflows/ci.yml/badge.svg)](https://github.com/L480/oura-exporter/actions/workflows/ci.yml)
[![GHCR](https://img.shields.io/badge/ghcr.io-l480%2Foura--exporter-blue?logo=github)](https://github.com/L480/oura-exporter/pkgs/container/oura-exporter)

Every data point of the [Oura Ring](https://ouraring.com) API in Prometheus, at the time it was
measured: each heart rate sample, the 5-minute sleep HRV, heart rate and sleep phases, MET per
minute, battery samples, workouts, sessions, tags and the daily scores. Based on
[legnoh/oura-exporter](https://github.com/legnoh/oura-exporter).

## How it works

Oura delivers data late, in bulk and with timestamps in the past, which a scrape cannot
represent. The exporter therefore **pushes samples with their real measurement time via
Prometheus remote write** and only serves its own health metrics on `/metrics`.

The receiver must accept remote write and out-of-order samples. Every poll re-reads the last
`OURA_LOOKBACK_DAYS` (default 3), so the out-of-order window has to be at least that long.

Prometheus: start it with `--web.enable-remote-write-receiver` and add to `prometheus.yml`:

```yaml
storage:
  tsdb:
    out_of_order_time_window: 7d
```

Mimir and Grafana Cloud: enable the out-of-order window for the tenant (`out_of_order_time_window`).

A receiver keeps the first value of a timestamp, so values Oura still revises (the last two activity
slots of today, a sleep period that just ended) are held back until they settle.

## Quick start

1. Create an application in the [Oura developer portal](https://cloud.ouraring.com/oauth/applications)
   and register the redirect URI `http://localhost:8000/callback`.
2. `cp .env.example .env` and set `OURA_CLIENT_ID`, `OURA_CLIENT_SECRET` and
   `OURA_REMOTE_WRITE_URL` (for example `http://prometheus:9090/api/v1/write`).
3. `docker compose run --rm -it oura-exporter`, open the link it prints, approve access, paste
   the address you land on and stop with Ctrl-C.
4. `docker compose up -d`. Samples show up in the receiver within a poll interval; `/metrics`
   on `http://127.0.0.1:8000` has the exporter's own health.

Load history with `oura-exporter backfill`, see [docs/details.md](./docs/details.md#backfill).
All options are in [`.env.example`](./.env.example). Headless setup, alerting and more are in
[docs/details.md](./docs/details.md).

## Metrics

Every series has `job="oura-exporter"`. Values Oura does not report are left out instead of
being 0, enums are numbers (the codes are in each metric's help text), and a few low-cardinality
fields such as the sleep type or the workout activity are labels.
